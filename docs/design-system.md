| 项目 | 内容 |
| --- | --- |
| 版本 | 1.0.0 |
| 适用端 | 桌面接收端（Electron/React）、手机网页（原生 TS）、配对与审批覆盖层 |
| 实现位置 | `src/renderer/styles.css`、`web/styles.css`、`src/renderer/Icons.tsx`、`web/index.html` |

## 1. 设计意图

EasyPush 的界面不是演示工具，而是**放在客厅、会议室里、可能整天亮着的公共屏幕**。设计由此派生四条硬约束：

1. **暗色为唯一主题**：避免大屏在暗环境里成为光源；不使用纯黑（`#000`），保留分层空间。
2. **琥珀色只代表"可操作的连接"**：二维码、主按钮、焦点环和直播状态使用同一强调色；绿色仅表示已建立/成功，红色仅表示拒绝/失败。
3. **连接信息永远可读**：配对码、地址、二维码在空闲态处于视觉中心，不因动画或装饰降低对比度。
4. **高风险动作必须慢下来**：审批覆盖层全屏遮罩、计数倒计时、明确列出设备与媒体类型；不使用自动聚焦以外的诱导性动画。

手机端与桌面端共享色板与语义，但**不共享字号与密度**：桌面是 13px 的高密度操作台，手机是 15px 的触控页面。

## 2. 色彩令牌

色值定义在 `:root`，桌面与手机仅存在极小差异（桌面的 `--radius` 为 16px，手机为 18px；桌面使用 Inter 优先，手机使用系统字体优先）。

### 2.1 背景与表面

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#08090a` | 应用底色、大屏留白 |
| `--bg-raised` | `#0c0e10` / `#0d0f11`（手机） | 标题栏、悬浮层底座 |
| `--surface` | `#101214` / `#101315`（手机） | 卡片 |
| `--surface-2` | `#15181b` / `#16191c`（手机） | 卡片内嵌块、输入框 |
| `--surface-3` | `#1b1f23` / `#1d2125`（手机） | 悬停、选中、次级按钮 |
| `--line` | 白色 7.5%–8% | 分隔线与卡片描边 |
| `--line-strong` | 白色 13%–14% | 强调描边、抽屉边界 |

### 2.2 文本

| 令牌 | 值 | 对比度（对 `--bg`） | 用途 |
| --- | --- | --- | --- |
| `--text` | `#f4f1ea` | 17.67:1 | 标题、主内容 |
| `--text-soft` | `#c9c4b9` | 11.46:1 | 正文、次级标题 |
| `--muted` | `#8b8f95` / `#8f939a`（手机） | 6.13:1 | 说明、时间、字段标签 |
| `--muted-2` | `#666b71` | 3.71:1 | 仅装饰性元数据（如刻度、占位符）；**不用于需要阅读的正文** |

`--muted-2` 低于 WCAG AA 4.5:1，使用范围受限；新增正文文本一律使用 `--muted` 及以上。

### 2.3 语义色

| 令牌 | 值 | 对比度 | 语义 |
| --- | --- | --- | --- |
| `--amber` | `#f3b64b` | 11.01:1 | 主操作、连接、焦点 |
| `--amber-bright` | `#ffc964` | — | 主按钮渐变高光 |
| `--amber-soft` | 琥珀 12% | — | 选中底、提示底 |
| `--amber-line` | 琥珀 30%–32% | — | 提示描边 |
| `--green` | `#5ad494` | 10.70:1 | 已连接、上传完成、直播中 |
| `--red` | `#f07a72` | 7.34:1 | 拒绝、错误、危险操作 |

颜色从不单独承载语义：状态同时有文案（"已配对"/"等待确认"）或图标，避免色觉差异导致误读。

## 3. 字体与排版

### 3.1 字族

```css
--font: "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI",
        "Noto Sans SC", "Microsoft YaHei", sans-serif;   /* 桌面 */
--font: -apple-system, BlinkMacSystemFont, "Segoe UI",
        "PingFang SC", "Hiragino Sans GB", "Noto Sans SC",
        "Microsoft YaHei", sans-serif;                    /* 手机 */
--mono: ui-monospace, "Cascadia Mono", "SFMono-Regular", "Consolas", monospace;
```

- 中文优先使用系统字体（苹方/微软雅黑/Noto Sans SC），保证手机与 Windows 的本地化字形。
- 等宽字体用于配对码、地址、码率/延迟、时间轴与日志；数字不跳动。
- 不使用网络字体：应用必须在无公网环境完整呈现，避免首屏闪烁与外部请求。

### 3.2 字号阶梯

| 场景 | 桌面 | 手机 |
| --- | --- | --- |
| 页面主标题 | 24–34px，字重 600 | `clamp(27px, 7.6vw, 34px)` |
| 卡片标题 | 13–15px / 600 | 16–17px / 600 |
| 正文 | 13px / 1.5 | 15px / 1.55 |
| 辅助说明 | 11–12px | 12–13.5px |
| 元数据/代码 | 10–11px mono | 11.5–13px mono |

桌面 `body` 为 13px；手机为 15px。移动端输入框字号不低于 16px 的规则由具体控件覆盖（配对码使用 30px 等宽），防止 iOS 自动缩放。

### 3.3 排版规则

- 行宽：桌面侧栏卡片内文本自然换行；手机正文最大宽度由 `@media (min-width: 1000px)` 的 `.app-main { max-width: 760px }` 限制。
- 字重只用 400/500/600/700，不引入可变字体。
- 全部界面文案使用简体中文；设备名、文件名等用户数据原样展示并做长度截断，不翻译。

## 4. 空间与形状

| 令牌/规则 | 值 |
| --- | --- |
| 桌面基础圆角 | 16px（`--radius`）；大屏舞台 20px；按钮 8–10px；状态胶囊 999px |
| 手机基础圆角 | 18px（`--radius`）；小圆角 12px；底部抽屉 22px（≥700px） |
| 桌面栅格 | `.app-body`：`minmax(0, 1fr) 356px`，侧栏固定宽；≤1120px 时侧栏 332px |
| 桌面内边距 | 主列 `20px 20px 20px 22px`；标题栏高 52px |
| 手机顶部栏 | 60px，含 `env(safe-area-inset-top)` |
| 手机横向留白 | 默认 16–18px；≤359px 时 13px；≥700px 时 24px |
| 触控目标 | 主要按钮 ≥46px 高；图标按钮 ≥40px；最小可点击区不低于 36px |

间距采用 4px 基准：4/6/8/10/12/14/16/20/24/32。不使用任意奇数间距，除非为视觉居中微调（1–2px）。

## 5. 布局

### 5.1 桌面接收端

```
┌──────────────────────────────────────────────┐
│ TitleBar 52px：品牌 · 设备名 · 状态 · 设置/日志/窗口 │
├──────────────────────────────┬───────────────┤
│ Stage（自适应，圆角 20px）     │ 侧栏 356px     │
│  空闲 / 直播 / 媒体 / 拖拽     │ ConnectCard    │
│                              │ LiveSignalCard │
│ Transport（媒体态）            │ InsertCard     │
│ QueuePanel（按需）             │ DevicesCard    │
│                              │ ActivityCard   │
│                              │ RailFoot       │
└──────────────────────────────┴───────────────┘
```

- 侧栏是**稳定的连接入口**：滚动发生在侧栏内部，舞台不随侧栏内容移动。
- 舞台使用绝对定位的三层（idle / live / media），以 220ms 透明度切换；同一时刻只有一层可交互，避免隐藏层抢焦点。
- ≤1120px 收窄侧栏与音量条；≤980px 隐藏品牌设备名与状态标签，仅保留图标与主状态。
- 审批覆盖层覆盖整个窗口，包括标题栏，阻止在待审批期间操作其他入口。

### 5.2 手机网页

- 单列滚动：顶部栏 → 直播面板（按需）→ Hero → 提示 → 投屏方式 → 上传 → DLNA → 使用须知 → 页脚。
- 投屏方式为两列卡片；≤359px 改为单列横向卡片（图标左、文字右）。
- ≥700px：内容留白增大，底部抽屉变为居中浮层（最大 560px / 82dvh）；直播舞台限制 420px 高。
- ≥1000px：主内容最大 760px，配对页最大 480px。
- 横屏且高度 ≤520px：隐藏配对页装饰图，直播舞台固定 54dvh，保证控件在首屏。
- 底部抽屉/提示使用 `100dvh` 与 safe-area，避免 iOS 地址栏与 Home 指示条遮挡。

## 6. 组件

### 6.1 按钮

| 变体 | 外观 | 用途 |
| --- | --- | --- |
| `.btn-primary` | 琥珀渐变、深色文字 | 允许、连接、主提交 |
| `.btn-secondary` | 表面 2 + 描边 | 次要确认（仅本次允许） |
| `.btn-ghost` | 透明 + 描边 | 拒绝、取消 |
| `.btn-soft` | 琥珀低透明度 | 轻量操作 |
| `.btn-danger` / `.btn-danger-soft` | 红底或红字 | 停止直播、移除设备 |
| `.btn-quiet` | 无底色 | 输入框内联提交 |

尺寸：默认 `min-height` 约 38px；`.btn-lg` 用于手机主提交；`.btn-sm` 用于卡片内小操作。禁用态统一 `opacity: .45` 且 `cursor: not-allowed`，不改变布局尺寸。

图标按钮（`.icon-btn`）必须有 `aria-label`；悬停/聚焦态使用表面提亮或琥珀描边，不用缩放。

### 6.2 卡片与连接信息

- `.card`：`--surface` 底、1px `--line` 描边、圆角 `--radius`，标题与说明采用"标题 + 一行解释"结构。
- `.connect-card` 依次呈现：二维码（HTTP 与 HTTPS 两张）、6 位配对码（等宽、逐位可读）、可复制地址、证书入口。
- 地址使用 `<code>` 与等宽字体；过长时中间省略，复制仍得到完整地址。
- 二维码容器固定宽高比，加载失败时保留占位与可复制的 URL，不塌陷布局。

### 6.3 舞台与播放控件

- 空闲态：品牌标识、连接提示与最近历史；不使用自动播放的视频背景。
- 直播态：全屏 `<video>` 黑底、设备名与实时指标（分辨率、帧率、码率、RTT）；控制条在底部，含静音、音量、全屏、停止。
- 媒体态：图片 `object-fit: contain`；视频/音频共用播放条；图片模式显示轮播开关与上一张/下一张。
- 进度条与音量使用原生 `input[type=range]` 的可访问语义，配套可见标签与当前值。
- `.queue-panel` 从舞台底部滑入，列出待播项；关闭按钮具备 `aria-label="关闭队列"`。

### 6.4 审批覆盖层

- 全窗口 `.overlay` + `role="dialog"` + `aria-modal="true"` + `aria-labelledby`。
- 固定信息顺序：请求类型（配对/投屏/接管）→ 设备名与平台/IP → 媒体类型与是否含音频 → 倒计时 → 允许/拒绝。
- 默认焦点在"允许"按钮（`autoFocus`）；拒绝按钮始终可见，不使用倒计时自动批准。
- 接管请求额外使用警告色与说明"原投屏会立即结束"。
- 60 秒倒计时以 `mm:ss` 显示；到点由服务端取消，界面不自行伪造结果。

### 6.5 表单与提示

- 输入框使用 `.field` 包裹可见 `<span class="field-label">`；不接受仅 placeholder 的字段。
- 错误文案放在表单内 `role="alert"` 的区域，同时保持统一话术（配对码错误不提示"还剩几次"）。
- Toast 使用 `aria-live="polite"`，最多同时 4 条，4.8–5.2 秒自动消失，可手动关闭；错误 Toast 不自动消失前需保证可读，当前实现仍自动消失，属已知取舍。
- 空状态、加载态、错误态三态齐备：加载使用 Spinner + 文案，不使用骨架屏伪装内容。

### 6.6 图标

- 桌面 `Icons.tsx` 与手机内联 `<symbol>` 精灵图，均为 24×24 viewBox 的实心路径。
- 尺寸梯度 14/18/22/26/30px；图标不单独承担含义，必须与文本或 `aria-label` 搭配。
- 新增图标必须同时加入两端资产，保持笔画视觉重量一致；禁止引入图标字体或外部 CDN。

## 7. 无障碍与已知缺口

已实现：

- 全局 `:focus-visible` 2px 琥珀描边、2px offset；键盘可完成配对审批、媒体控制与设置。
- 桌面快捷键：`Space` 播放/暂停（媒体态、非输入焦点），`Escape` 关闭最上层设置/日志/队列。
- 手机底部抽屉：打开时聚焦关闭按钮，`Tab` 循环限制在抽屉内，`Escape` 关闭并恢复原焦点（`web/ui.ts`）。
- 对话框均声明 `aria-modal` 与标题关联；上传列表、待审批区、Toast 使用 live region。
- 切换动画在 `prefers-reduced-motion: reduce` 下压缩到 0.001ms，不依赖动画传达状态。
- 文本与关键控件的对比度达到 AA（见 §2.2）；状态不只靠颜色。

已知缺口（不隐瞒）：

1. **桌面端审批/设置/日志弹窗没有焦点陷阱**：`ApprovalOverlay.tsx`、`SettingsModal.tsx`、`LogsModal.tsx` 仅设置 `autoFocus`，`Tab` 仍可移动到遮罩后的控件。手机抽屉已实现陷阱，桌面端待补齐。
2. **桌面弹窗关闭后不恢复焦点**到触发按钮；手机抽屉已恢复。
3. 部分装饰性元数据使用 `--muted-2`（3.71:1），不适合低视力用户长时间阅读。
4. 未做屏幕阅读器逐流程实测（VoiceOver/TalkBack/NVDA），仅完成语义与键盘静态检查。

修复第 1、2 项应复用 `web/ui.ts` 的 `focusables()`/循环逻辑，或在桌面端引入统一的 `useDialogFocus`；在补齐前，发布说明不得宣称"完全无障碍"。

## 8. 动效

- 时长：交互反馈 120ms，层次切换 220ms，抽屉 260–320ms；缓动以 `ease`/`ease-out` 为主。
- 仅动画 `opacity` 与 `transform`，避免布局抖动；不使用视差、粒子或持续背景动画。
- 直播信号使用低幅度脉冲（`.signal`/`.pending-radar`），播放控制不使用循环动画。
- 动效不得延迟关键信息出现；审批卡片与配对码在首帧即可读。

## 9. 响应式与平台差异

| 条件 | 行为 |
| --- | --- |
| 桌面窗口 <1120px | 侧栏 356→332px，隐藏状态地址，缩短音量条 |
| 桌面窗口 <980px | 隐藏品牌设备名与状态文字，仅保留图标与状态点 |
| 手机 <360px | 投屏卡片单列，减小页面左右留白 |
| 手机 ≥700px | 抽屉居中、直播舞台限高、更大留白 |
| 手机 ≥1000px | 内容限宽 760px，配对页限宽 480px |
| 横屏高度 ≤520px | 隐藏配对装饰、直播舞台 54dvh |
| `prefers-reduced-motion` | 动画与过渡近似关闭 |
| 桌面平台 | 仅桌面显示"共享屏幕"入口；手机端隐藏 |
| HTTP 访问 | 显示"当前为 HTTP 连接"警告，摄像头入口禁用并引导安装证书 |

字号不随视口整体缩放（除主标题 `clamp`），保证系统字号设置与浏览器缩放仍然有效。
