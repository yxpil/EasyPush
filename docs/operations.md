# EasyPush 运维手册

| 项目 | 内容 |
| --- | --- |
| 版本 | 1.0.0 |
| 适用系统 | Windows 10/11 x64（接收端）；iOS Safari 16+、Android Chrome 120+（发送端） |
| 默认端口 | HTTP 7333 / HTTPS 7443 / DLNA SSDP UDP 1900 |
| 数据目录 | `%APPDATA%\EasyPush`（卸载后默认保留） |
| 状态 | 代码与自动化验证完成；真机与干净虚机签收见 [验证规范](verification.md#5-真机矩阵) |

## 1. 安装与首次启动

1. 运行 `EasyPush-1.0.0-x64.exe`。安装程序为按用户安装（`perMachine: false`），可选择安装目录，创建桌面与开始菜单快捷方式。
2. 安装包**未做代码签名**，Windows SmartScreen 可能显示"未知发布者"。此时应核对安装包 SHA-256（见 [验证规范](verification.md#7-打包产物验证)）后再决定是否继续；组织内分发应由管理员统一校验。
3. 首次启动时，Windows 防火墙会询问网络访问。**仅勾选专用网络**，不要对公用网络开放。
4. 应用启动后显示连接卡片：HTTP/HTTPS 二维码、6 位配对码、局域网地址、证书下载入口。关闭窗口默认最小化到托盘（可在设置中关闭该行为）。
5. 同一用户会话只允许一个实例；重复启动会唤醒已有窗口。

### 1.1 端口

- HTTP 默认 `7333`，HTTPS 默认 `7443`。若被占用，最多尝试 10 个端口（含首选，即向后顺延 9 个，如 7334、7335…），界面、二维码与防火墙按钮使用**实际监听端口**。
- 修改端口会重启 HTTP/HTTPS 服务，已配对设备可能短暂断线；需重新运行"安装防火墙规则"。
- 端口范围限制为 1024–65535。不要与系统服务或开发服务器冲突。

### 1.2 防火墙

推荐在设置中点击"安装防火墙规则"，通过 UAC 创建：

- `EasyPush_TCP`：入站允许，TCP，当前 HTTP/HTTPS 端口；
- `EasyPush_UDP`：入站允许，UDP，1900（DLNA SSDP）。

等价的手工命令（管理员 PowerShell，端口以实际值为准）：

```powershell
netsh advfirewall firewall add rule name=EasyPush_TCP dir=in action=allow protocol=TCP localport=7333,7443
netsh advfirewall firewall add rule name=EasyPush_UDP dir=in action=allow protocol=UDP localport=1900
```

仅在**专用网络**配置文件下使用。若 Windows 将当前 Wi-Fi 标记为"公用"，手机将无法连接；应在系统设置中把该网络改为专用，或不要使用公共 Wi-Fi。

## 2. 网络要求

| 需求 | 说明 |
| --- | --- |
| 同一子网 | 手机与电脑连接同一路由器/AP；跨 VLAN、访客网络通常不可达 |
| 客户端隔离 | 必须关闭 AP 的"客户端隔离/AP isolation"，否则设备互不可见 |
| 组播 | DLNA 需要允许 UDP 1900 与组播；部分企业 AP 默认禁用 |
| 公网 | 不需要，也不支持。无 STUN/TURN、无中继、无云端 |
| VPN | 可能抢占默认路由或产生虚拟网卡；建议投屏时断开 VPN |
| 多网卡 | 应用优先选择私有 IPv4、Wi-Fi/以太网，降低虚拟网卡权重；可在设置中固定首选地址 |

HTTPS 证书按当前局域网 IP 与主机名签发。IP 变化后应用会在约 15 秒内重新探测并重签叶证书；手机需使用新地址/新二维码，旧页面的连接会中断。

## 3. 证书与手机信任

摄像头直播与桌面屏幕共享要求浏览器处于**安全上下文**（HTTPS）。EasyPush 在首次启动时现场生成本地 CA 与服务器叶证书，不依赖公网、不写入系统信任，必须由用户在**每台发送设备**上手动信任 CA。

### 3.1 证书构成

| 文件（`%APPDATA%\EasyPush\certs\`） | 内容 |
| --- | --- |
| `local-ca.pem` | 本地根 CA 证书（RSA-2048 / SHA-256，有效期 3650 天） |
| `local-ca-key.json` | CA 私钥。`safeStorage` 可用时加密；不可用时为明文 base64（见 §3.6） |
| `server.pem` / `server-key.json` | 服务器叶证书与私钥（365 天，到期前 30 天或 SAN 变化时重签） |
| `meta.json` | SAN 列表、到期时间、CA SHA-256 指纹 |

TLS 最低版本 1.2。叶证书 SAN 包含当前所有网卡 IPv4、`localhost`、`127.0.0.1` 与主机名（含 `.local`）；不包含公网域名。HTTPS 响应发送 `Strict-Transport-Security: max-age=0`，便于 IP 变化后立即回退，不启用 HSTS 强制。

CA 下载地址：`http://<局域网IP>:<HTTP端口>/ca.crt`（也接受 `/EasyPush-CA.crt`），下载文件名为 `EasyPush-CA.crt`。界面显示 CA SHA-256 指纹；安装前应核对指纹一致。

### 3.2 Windows 接收端

接收端自身通过回环 `http://127.0.0.1:<HTTP端口>/desktop/` 加载界面，**不需要**信任 CA。只有在 Windows 浏览器作为发送端共享屏幕时，才需要在该浏览器所在系统信任 CA：

1. 下载 `EasyPush-CA.crt`。
2. 双击 → "安装证书" → 选择"当前用户"或"本地计算机"。
3. 存储位置选择"受信任的根证书颁发机构" → 完成 → 确认安全警告。
4. 完全退出并重启浏览器；使用 HTTPS 二维码/地址打开页面。

企业设备可能由组策略禁止用户安装根证书，此时需 IT 审批；不要通过关闭浏览器安全策略绕过。

### 3.3 Android

不同厂商菜单名称略有差异，通常为：

1. 用手机浏览器打开 `http://<IP>:7333/ca.crt` 下载（Android 可能提示"此类型文件可能有害"，选择仍要下载）。
2. 设置 → 安全（或"密码与安全"）→ 更多安全设置 → 加密与凭据 → 安装证书 → **CA 证书**。
3. 选择下载的 `EasyPush-CA.crt`，确认"你的数据可能被监控"警告。
4. 使用 HTTPS 地址重新打开 EasyPush，摄像头入口应可用。

注意：

- Android 7+ 的应用默认不信任用户 CA；Chrome 等浏览器通常信任。个别投屏 App 若使用系统 WebView 且未放开用户 CA，仍会失败。
- 部分系统要求先设置锁屏密码才能安装 CA。
- Android 11+ 不再支持从浏览器直接跳转安装，必须走系统设置。
- 移除：设置 → 加密与凭据 → 用户凭据 → 选择 EasyPush CA → 删除。

### 3.4 iOS / iPadOS

1. **使用 Safari** 打开 `http://<IP>:7333/ca.crt`，允许下载描述文件。
2. 打开"设置" → 顶部"已下载描述文件" → 选择 EasyPush CA → 安装（输入锁屏密码）。
3. 设置 → 通用 → 关于本机 → **证书信任设置** → 打开 EasyPush CA 的完全信任开关。
4. 关闭并重新打开 Safari，使用 HTTPS 地址。

只完成第 2 步而未开启"证书信任设置"是最常见失败原因：页面能打开但摄像头仍被拒绝。用 Chrome/Edge iOS 版下载描述文件可能落入"文件"App，建议始终用 Safari。

移除：设置 → 通用 → VPN 与设备管理 → 删除描述文件；再到证书信任设置关闭。

### 3.5 macOS（发送端）

1. 下载 `EasyPush-CA.crt`，双击导入"钥匙串访问"。
2. 选择"系统"钥匙串，找到 EasyPush CA，双击 → 信任 → "使用此证书时"设为"始终信任"。
3. 输入管理员密码确认；重启浏览器。

仅用于桌面浏览器屏幕共享；EasyPush 不提供 macOS 接收端安装包。

### 3.6 安全边界

- 该 CA 是设备上的**根证书**，理论上可签发任意域名的证书。只应在自己的设备上安装，并仅在你信任的局域网使用。
- 不需要摄像头/屏幕共享时，建议**不要安装 CA**；HTTP 网页仍可上传照片与视频。
- 不再使用 EasyPush 或更换电脑后，应从手机/电脑中删除该 CA，并删除应用数据目录中的 `certs/`。
- CA 私钥不离开接收端；删除 `certs/` 后所有设备需重新下载并信任新 CA。
- 若 `safeStorage` 不可用，`local-ca-key.json` 为明文 base64。此时应确保 Windows 账户与磁盘加密（BitLocker）到位，并限制数据目录权限。

## 4. 日常操作

### 4.1 配对

1. 手机扫码或打开桌面地址；二维码中的 ticket 120 秒有效，使用一次即轮换。
2. 也可输入桌面 6 位配对码（5 分钟有效，过期自动轮换）。
3. 电脑弹出审批卡片，核对设备名、平台与 IP。选择"允许并记住"或"仅本次允许"；拒绝不创建会话。
4. 记住的设备获得设备凭据，Cookie 丢失后可恢复；会话 30 天有效。
5. 桌面侧栏可查看已配对设备并移除；被移除设备需重新配对。

配对码错误有 IP 与全局双重限速（同 IP 5 分钟 6 次、全局 10 分钟 30 次）。持续失败时等待限速窗口结束，不要在界面反复尝试。

### 4.2 投屏

- **摄像头**：手机网页选择"摄像头" → 可选麦克风 → 电脑审批 → 建立 WebRTC。桌面可静音、调音量、全屏、停止。
- **屏幕共享**：仅桌面浏览器显示入口；选择标签页/窗口/整屏 → 电脑审批。浏览器原生"停止共享"会结束会话。
- **上传**：选择文件或拖拽到桌面窗口；图片自动轮播（默认 8 秒，可调 2–600 秒）；视频/音频可暂停、Seek、切歌。
- **DLNA**：在同一网络的 DLNA App 中选择"EasyPush"渲染器；直播中收到推送会返回忙碌。
- 同一时刻只允许一个直播。新请求可选择"结束原投屏并接管"。

### 4.3 自动批准（谨慎开启）

设置中的"自动批准"会**同时跳过配对审批与直播审批**，但"接管"仍需人工确认。开启后，局域网内任何能访问端口的设备都可直接建立新会话。仅在完全可信、隔离的演示网络短期使用；使用完毕立即关闭。该行为的残余风险见 [ADR-014](adr.md#adr-014自动批准跳过直播审批) 与 [安全设计](security.md)。

## 5. 数据、日志与诊断

| 路径 | 内容 | 保留策略 |
| --- | --- | --- |
| `%APPDATA%\EasyPush\state.json` | 设置、设备、会话、历史 | 持续；设备上限 500，历史上限 200 |
| `...\uploads\` | 上传的媒体文件 | 7 天。仅在**应用启动时**清理一次；长期不重启则不会中途清理 |
| `...\certs\` | CA、叶证书、私钥、元数据 | 持续；叶证书到期前 30 天自动重签 |
| `...\logs\easypush-YYYY-MM-DD.jsonl` | 按天 JSONL 日志 | 14 天；界面显示最近 400 条，缓冲上限 500 |
| `...\runtime.json` | 端口、URL、PID、启动时间等诊断信息 | 运行期间存在，正常退出时删除 |

设置中可"打开数据目录""打开日志目录""复制诊断信息""清空上传"。

诊断信息包含版本、系统、Electron/Chrome/Node 版本、服务器信息、设置、设备列表（名称/平台/IP）、当前直播与媒体状态、最近 80 条日志。日志按键名脱敏 `token/secret/cookie/authorization/ticket/credential/password`，但**设备名、IP、文件名可能包含个人信息**；对外分享前请自行检查。诊断信息不包含 Cookie 或私钥。

### 5.1 备份与迁移

- 需要保留配对设备与设置：退出应用后复制整个 `%APPDATA%\EasyPush`（含证书）。迁移到新机器后，旧 CA 仍被手机信任，但新 IP 会触发叶证书重签。
- 只需要设置：复制 `state.json`。设备令牌与 CA 不匹配时会导致旧会话失效，需重新配对。
- 不建议备份 `uploads/` 作为长期存储；它们是临时投送文件。

### 5.2 清理

- 清空上传：设置 → "清空上传"，会停止当前上传媒体的播放并删除 `uploads/` 内容。
- 重置全部状态：退出应用 → 删除 `%APPDATA%\EasyPush` → 重启。此操作不可恢复，且所有设备需重新配对、重新信任 CA。
- 卸载程序默认**不删除**用户数据（`deleteAppDataOnUninstall: false`），需手动清理上述目录。

## 6. 升级与卸载

- 覆盖安装新版本会保留 `%APPDATA%\EasyPush`。升级前建议退出应用，避免文件占用。
- 升级后如端口或 IP 变化，重新生成二维码并检查防火墙规则。
- 卸载通过"设置 → 应用 → EasyPush → 卸载"或安装目录中的卸载程序。卸载不会终止已复制到其他位置的文件。
- 卸载后如需彻底清除：删除 `%APPDATA%\EasyPush`，并在手机端删除 CA 描述文件/用户凭据。

## 7. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 手机打不开页面 | 不同网络、AP 隔离、防火墙拦截、VPN | 确认同一 Wi-Fi；关闭客户端隔离；检查专用网络防火墙规则；断开 VPN；用 `ping <IP>` 验证连通 |
| 页面能开，扫码后提示过期 | ticket 120 秒过期或已被使用 | 刷新桌面二维码重新扫描；或改用 6 位配对码 |
| 配对码总是不对 | 桌面码已轮换；输入法全角 | 使用最新桌面显示的码；切换半角数字；等待限速窗口结束 |
| 摄像头入口灰/提示不安全 | HTTP 页面或 CA 未信任 | 安装 CA → 用 HTTPS 二维码打开；iOS 检查"证书信任设置"；Android 确认安装的是 CA 证书 |
| 摄像头有画面无声音 | 未勾选麦克风、系统静音、桌面音量 0 | 重新发起并允许麦克风；检查桌面静音/音量；确认手机未占用麦克风 |
| 屏幕共享入口不显示 | 手机端、浏览器不支持、HTTP | 仅在桌面 Chrome/Edge + HTTPS 下使用；确认 `getDisplayMedia` 可用 |
| 投屏卡顿/模糊 | Wi-Fi 弱、2.4 GHz、码率上限、CPU 解码 | 靠近 AP/使用 5 GHz；关闭省电模式；降低同时运行的高负载程序；查看桌面统计中的码率与 RTT |
| 直播中断后无法恢复 | 超过 8 秒宽限、手机关屏/切后台 | 重新发起投屏；保持页面在前台；检查手机是否限制后台网络 |
| DLNA 设备列表找不到 EasyPush | UDP 1900 被拦、组播关闭、DLNA 被禁用 | 允许 UDP 1900；在设置中启用 DLNA；关闭 AP 组播过滤；重启应用与电视 |
| DLNA 推送后无法播放 | 编码/容器不受支持、URL 不可达 | 换 H.264/AAC/MP3/JPEG；确认媒体 URL 对电视可达；查看桌面错误提示 |
| 上传 413/415 | 超过 2 GB、空文件、类型不支持 | 压缩或分割文件；空文件无意义；转码为常见格式 |
| HEIC/HEVC 不能播放 | Electron/Chromium 解码限制 | 转为 JPEG/H.264；这是已知限制，不是上传失败 |
| 端口被占用/地址变化 | 其他服务占用、DHCP 重新分配 | 查看界面实际端口；重启路由器或设置静态租约；重新扫码 |
| 关闭窗口后找不到应用 | "关闭到托盘"开启 | 双击托盘图标恢复；托盘菜单可退出 |
| 启动报"无法启动本地服务" | 端口耗尽、权限、数据目录不可写 | 查看日志目录；关闭占用端口的程序；确认 `%APPDATA%` 可写 |
| 界面白屏/崩溃 | 渲染进程异常 | 应用会自动重载；仍失败则查看日志并重启；必要时备份后重置数据目录 |

## 8. 安全运维清单

- [ ] 首次部署后立即确认"自动批准"为关闭。
- [ ] 仅在专用网络开放防火墙；不要在咖啡厅/机场等公用网络开启。
- [ ] 定期检查设备列表，移除不再使用的设备。
- [ ] 不需要摄像头时不要安装 CA；更换电脑后从手机删除旧 CA。
- [ ] 共享诊断信息前检查 IP、设备名、文件名。
- [ ] 保持 Windows 与 Electron 版本更新；关注依赖安全公告。
- [ ] 安装包未签名，分发时提供 SHA-256 并由管理员核验。
- [ ] 若 CA 私钥疑似泄露：退出应用 → 删除 `certs/` → 重启 → 在所有设备删除旧 CA 并重新信任。
- [ ] 不要把端口映射到公网，不要配置反向代理暴露 `/desktop` 或 `/media`。

## 9. 能力与支持边界

- 不提供手机整屏镜像、公网投屏、云端录制、账号体系、远程控制。
- 不提供自动更新；升级需手动安装新版本。
- 不收集遥测，不提供远程协助；故障排查依赖本地日志与用户提供的诊断信息。
- 未签名的安装包可能被安全软件拦截；这是分发限制，不是应用行为。
- 性能目标（720p30 ≤4 Mbps、1080p30 ≤8 Mbps）为设计上限，实际取决于网络、手机编码能力与桌面解码能力。
