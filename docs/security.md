| 项目 | 内容 |
| --- | --- |
| 版本 | 1.0.0 |

## 1. 安全目标

1. **未配对设备不能读取媒体、不能上传、不能发起直播。**
2. **配对与直播必须由电脑前的人确认**（除非用户显式关闭审批）。
3. **局域网内的恶意网页不能借用户浏览器调用本机 API。**
4. **桌面界面与上传媒体不能被局域网设备直接访问。**
5. **摄像头/屏幕流只在发送端与接收端之间传输，不经过第三方。**
6. **敏感凭据不进入日志、不写入 URL、不以明文返回。**
7. **安全控制在真实协议层验证**，而不是只做单元测试或代码宣称。

非目标：抵御已取得当前 Windows 用户权限的恶意软件、抵御拥有主机管理员权限的攻击者、提供企业级身份联邦或审计合规认证。

## 2. 资产与攻击面

| 资产 | 位置 | 影响 |
| --- | --- | --- |
| 摄像头/屏幕实时流 | WebRTC（P2P） | 隐私泄露 |
| 上传的照片/视频 | `uploads/` | 隐私泄露、磁盘占用 |
| 配对码/ticket | 桌面 UI、二维码 | 未授权配对 |
| 会话令牌/设备凭据 | Cookie、`state.json` | 冒充已配对设备 |
| CA 与叶证书私钥 | `certs/` | 伪造任意 HTTPS 站点（若 CA 被信任） |
| 设备列表、IP、历史 | `state.json`、UI | 信息泄露 |
| 日志 | `logs/` | 凭据/网络信息泄露 |
| 主机网络位置 | 系统 | 被当作跳板访问内网 |

攻击面：

- `0.0.0.0:7333` / `0.0.0.0:7443` 的 HTTP/HTTPS/WS；
- UDP 1900 SSDP 与 `/dlna/*` SOAP/GENA；
- 回环 `/desktop/*`、`/media/*` 与 Electron IPC；
- 浏览器获取摄像头、麦克风、屏幕的权限入口；
- 媒体解码器（Chromium）与上传文件内容；
- 依赖供应链与未签名安装包。

## 3. 信任边界与攻击者模型

| 攻击者 | 能力 | 主要目标 |
| --- | --- | --- |
| A. 同网未配对设备 | 扫描端口、访问网页/API、发送 WS、SSDP、SOAP | 配对、直播、读取媒体 |
| B. 恶意网页 | 在受害者浏览器中发起跨站请求、嵌入 iframe | CSRF、DNS rebinding、点击劫持 |
| C. 开放 Wi-Fi 窃听者 | 被动嗅探、ARP/DNS 欺骗、HTTP 篡改 | 令牌、配对码、媒体 |
| D. 恶意 DLNA 控制器 | 任意 SOAP、订阅、回调 | 上屏、内网探测、事件伪造 |
| E. 已配对但失陷设备 | 有效 Cookie/凭据 | 上传、反复请求直播 |
| F. 同机其他用户/低权限进程 | 读取用户目录、访问回环端口 | 私钥、媒体、桌面接口 |
| G. 供应链攻击者 | 依赖/安装包替换 | 代码执行 |

## 4. 控制措施

### 4.1 配对与授权

- 两条路径：二维码 ticket（120s，使用即轮换）或 6 位码（300s 轮换）。
- 配对必须落到 `PairingRequest`，桌面 UI 展示设备名、平台、IP、倒计时；默认需要人工点“允许并记住”。
- 限速：ticket 单 IP 12 次/分钟；配对码单 IP 6 次/5 分钟 + 全局 30 次/10 分钟；`safeEqual` 常量时间比较。
- 已被移除/禁止的设备无法恢复；设备凭据只保存 HMAC-SHA256（密钥为 `state.json` 中的随机 `serverSecret`）。
- 会话令牌 30 天，签名覆盖版本、设备 ID、过期时间与 nonce；服务端只接受格式、签名、过期、设备存在且未禁用四者同时满足。
- 审批轮询绑定发起 IP；不匹配统一返回 `expired`，不泄露请求状态。
- “自动批准”是显式高风险开关：同时跳过配对审批与直播审批（接管仍需确认）；设置页有警示文案。见 [ADR-014](adr.md#adr-014自动批准跳过直播审批)。

### 4.2 会话与跨站防护

- Cookie：`ep_session`、`HttpOnly`、`SameSite=Strict`、`Path=/`、30 天；HTTPS 下 `Secure`。
- API 对 `Sec-Fetch-Site: cross-site` 直接 403；写操作在带 `Origin` 时必须与 `Host` 同源。
- 写接口要求 `Content-Type: application/json`，跨源请求会触发预检；服务端不返回 CORS 许可头。
- 所有请求校验 Host 允许列表（回环、RFC1918、本机主机名及 `.local`，IDNA 归一化），阻断 DNS rebinding 常用手法（公网域名解析到私网仍带公网 Host）。
- 网页 CSP `default-src 'self'`、`object-src 'none'`、`base-uri 'none'`、`frame-ancestors 'none'`；另有 `X-Frame-Options: DENY`、COOP、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`。
- 桌面页 CSP 不允许摄像头/麦克风；网页 HTML 通过 `Permissions-Policy` 只允许自身使用摄像头、麦克风、屏幕捕获。

### 4.3 回环隔离

- `/desktop/*` 与 `/media/:id` 只接受 `127.0.0.0/8` 或 `::1`；局域网请求返回 403。
- Electron 窗口只加载回环 `/desktop/`；导航目标被限制，拒绝新窗口与 `webview` 挂载。
- IPC 每个通道先校验：调用方必须是主窗口 `webContents`，且 `senderFrame.url` 以 `${desktopOrigin}/desktop` 开头；随后按通道做类型、长度、枚举校验。
- 渲染进程启用 `contextIsolation`、`sandbox`，关闭 Node 集成；preload 只暴露白名单 API。

### 4.4 上传与媒体处理

- 上传必须已配对；单设备 5 分钟 30 次。
- 以流方式写入 `.part`，声明值与实际字节双重限制 2 GB；空文件拒绝；写入前检查可用磁盘。
- MIME 仅允许 `image/*`、`audio/*`、`video/*` 与 HLS；文件名去除目录、控制字符与危险符号；落盘名为随机 ID + 白名单扩展名。
- 上传目录与文件权限 0600（在 Windows 上受用户目录 ACL 约束），临时文件失败即删除；7 天自动清理。
- 媒体 URL 使用 12 位随机 ID；仅回环可读；支持 Range，不执行文件而是交给浏览器解码。
- DLNA/URL 直链只接受 http/https，长度 ≤2048；不经过服务端代理，避免服务端 SSRF 读取响应。

### 4.5 TLS 与证书

- 本地 CA：RSA-2048、SHA-256、`basicConstraints CA:true`、`keyCertSign`，有效期 3650 天。
- 叶证书：RSA-2048、SHA-256、`serverAuth`，有效期 365 天，提前 30 天续签；SAN 覆盖所有私有 IPv4、主机名与 `.local`，IDNA 归一化。
- HTTPS 最低 TLS 1.2；证书仅用于局域网地址，不包含公网域名。
- CA 下载端点只返回公钥证书；私钥不通过 HTTP 暴露。
- 私钥使用 Electron `safeStorage`（Windows DPAPI）加密后写入 `certs/*.json`；**若系统不支持 safeStorage，则退化为 base64 明文存储**，此时安全性依赖用户目录 ACL。日志不记录私钥。
- 使用 `Strict-Transport-Security: max-age=0` 而非长期 HSTS，避免 IP 变化/端口迁移后浏览器无法回退；这是可用性与安全性的明确取舍（[ADR-004](adr.md#adr-004自建本地-ca-而非公网证书)）。

### 4.6 WebSocket 与 WebRTC

- `/ws` 升级阶段校验路径、Host、Origin、会话；未授权直接 HTTP 拒绝，不进入 WS。
- 单帧 512 KiB；每设备 10 秒 180 条；服务端 ping/pong 30 秒清扫；重复连接替换旧连接。
- SDP、candidate、设备名、结束原因均有长度/类型限制；消息解析使用显式判别联合，不信任客户端字段。
- WebRTC 不配置 STUN/TURN，仅 host candidate；首帧前不把桌面 SDP/ICE 发给未通过审批的设备。
- 桌面端在审批通过且渲染器就绪后才 `prepare`；渲染器异常会结束会话，避免“后台仍在采集”。
- 摄像头/麦克风/屏幕权限由浏览器提示；服务端不缓存媒体流。

### 4.7 DLNA 边界

- SSDP 只处理私网/回环来源；`/dlna/*` 同样限制，公网源 403。
- SOAP 仅接受 `text/xml`、动作与 `SOAPACTION` 一致、体积 ≤128 KiB；未知服务/动作/实例 ID 返回标准 fault。
- 控制限速 1200 次/分钟/IP；事件回调只允许 http，且 host 必须等于订阅者 IP，禁止 1900 端口，降低 SSRF/反射放大风险。
- DLNA 本身无认证（协议设计如此），因此任何同网设备都能让接收端播放媒体；这是能力与安全的权衡，见残余风险。

### 4.8 日志与隐私

- 日志字段按键名脱敏：`token`、`secret`、`cookie`、`authorization`、`ticket`、`credential`、`password`；长字符串截断 512 字符。
- 日志只落本机；无遥测、无远程上报、无崩溃上传。
- 诊断信息包含版本、端口、设备摘要、近期日志，不包含会话令牌与私钥；由用户主动复制。
- 历史记录保留设备名、IP、分辨率、码率、结束原因，供本机排查，不对外发送。

### 4.9 供应链与构建

- 依赖版本精确锁定，`package-lock.json` 入库；构建在 CI 中从锁文件 `npm ci`。
- Electron 启用 ASAR、fuses 未额外修改；安装包当前**未签名**，SmartScreen 可能警告。
- CI 运行类型检查、lint、单元/集成与 E2E；构建产物作为失败诊断附件上传。
- 未执行依赖漏洞扫描与 SBOM 生成，属于发布前缺口。

## 6. 已验证的安全行为

`tests/e2e/security.spec.ts`（7 个用例）在真实 HTTP/HTTPS/TLS/WS 层验证：

1. 安全响应头、CSP、Permissions-Policy、CA 下载与指纹、叶证书 SAN/有效期、TLS 1.2/1.3、公网信任拒绝。
2. 未认证 `/api/me` 401；配对审批后 Cookie 属性；令牌可用；伪造令牌 401。
3. 外来 Host 421；外来 Origin 403；`Sec-Fetch-Site: cross-site` 403；跨站上传 403。
4. 未认证上传 401；不支持类型 415；空文件 400；声明 3 GB 413；合法 PNG 201。
5. 局域网页面 200；局域网访问 `/desktop`、`/media` 403；本机媒体 200/Range 206；穿越拒绝；HTTP 无 HSTS。
6. 匿名 WS 401；外来 Origin 403；授权连接 101 且 hello 字段正确。
7. 连续错误配对码第 7 次触发 429，且不创建设备。

配套单元/集成测试覆盖 Host/cookie/令牌/限速/CSP 生成等纯逻辑。证据与命令见 [验证规范](verification.md)。

## 7. 残余风险

1. **首次 HTTP 访问与 CA 下载**：手机首次通过 HTTP 打开页面时，理论上可被同网 MITM 篡改。设置页显示 CA SHA-256 指纹，用户应在安装前核对；更好的方案是预置证书或使用带外校验，本版本未实现。
2. **HTTP 会话**：未强制 HTTPS 时，Cookie 不带 `Secure`，同网嗅探者可窃取会话并上传/请求直播（直播仍需审批，除非自动批准）。
3. **自动批准**：开启后同网任何人都能配对并发起直播（接管除外）。这是为受控演示场景提供的便利，默认关闭。
4. **DLNA 无认证**：同网任何控制器都能上屏、调音量；这是 DLNA 的协议属性，家庭/会议室网络应视为可信任。
5. **safeStorage 不可用**：私钥退化为 base64 明文；能读取用户目录的同机进程可取得 CA 私钥。现代 Windows 正常安装通常可用。
6. **同用户恶意软件**：可读取用户目录、解密 DPAPI 数据、访问回环端口；不在本产品防御范围。
7. **未签名安装包**：用户无法通过发布者签名验证来源；正式分发前应完成代码签名与校验和发布。
8. **DoS**：限速降低滥用，但没有连接数上限、IP 封禁或流量整形；同网攻击者仍可造成服务不可用。
9. **媒体解码攻击面**：上传/远程媒体交给 Chromium 解码；未做模糊测试，未知解码漏洞的风险由 Electron 更新节奏承担。
10. **无安全审计/渗透测试**：当前只有作者自测与自动化用例，不构成第三方安全保证。

## 8. 运维安全清单

- [ ] 仅在可信局域网启用；不要在公网/咖啡厅 Wi-Fi 直接暴露端口。
- [ ] 保持 Windows 专用网络配置文件，避免公用网络下的入站阻断（或明确放行）。
- [ ] 优先使用 HTTPS 二维码；安装 CA 前在设置页核对 SHA-256 指纹。
- [ ] 不开启自动批准，除非是受控演示且现场人员可信。
- [ ] 定期检查已配对设备，移除不认识的条目；设备丢失时立即移除。
- [ ] 怀疑 CA 泄露时：退出应用 → 删除 `certs/` → 重启 → 在所有设备删除旧根证书 → 重新安装新 CA。
- [ ] 保持 Electron/依赖更新；安装包只从可信构建产物获取。
- [ ] 不把 `state.json`、`certs/`、`logs/` 上传到公开仓库或聊天工具。

## 9. 漏洞报告

这是个人开源项目。发现问题请通过仓库的 **GitHub Security Advisory**（私密报告）提交，包含版本、复现步骤、影响与 PoC。请勿在公开 issue 中粘贴会话令牌、证书私钥或他人隐私媒体。维护者会在确认后发布修复与致谢；本版本不承诺 SLA。
