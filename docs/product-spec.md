## 1. 背景与问题

会议室、教室、家庭场景中，把手机里的照片、视频或摄像头画面放到电脑大屏，通常需要安装 App、登录账号或依赖公网服务。访客设备型号复杂、网络不可信、IT 不愿意开放云账号，导致"临时投一下"成本很高。

EasyPush 的目标是做一个**零安装、局域网内、可审计**的接收端：

- 发送端只需要浏览器，扫码 + 配对码即可；
- 数据不经过公网，媒体与信令只在本机与局域网之间流动；
- 接收端对每次配对、每次直播都保留人工审批；
- 同时兼容 DLNA，覆盖不支持浏览器的电视/投屏 App 生态。

## 2. 目标与非目标

### 2.1 目标

1. 访客在 60 秒内完成连接并发起第一次投送（设计目标，真机实测记录）。
2. 手机拍照/选文件 → 电脑大屏可见，单文件最大 2 GB。
3. 手机摄像头直播端到端延迟与画质可用：720p/30fps 上限 4 Mbps（设计目标）。
4. 桌面浏览器可共享标签页/窗口/整屏，1080p/30fps 上限 8 Mbps（设计目标）。
5. 标准 DLNA 控制器可以发现并向 EasyPush 推送图片/音视频。
6. 所有高风险动作（配对、直播）默认需要电脑端审批。
7. 不依赖公网、不依赖账号、不写入系统证书信任（由用户自愿安装 CA）。

### 2.2 非目标

- 手机整屏镜像（浏览器安全模型不允许）。
- iOS/Android 原生 App、后台常驻发送端。
- 跨公网/跨 NAT 投屏，云端录制、转码、账号体系。
- 手机反向控制电脑、远程桌面。
- 多接收端集群、负载均衡。
- macOS/Linux 安装包（代码层面尽量跨平台，本版本只发布 Windows x64）。

## 4. 能力边界（必须向用户明示）

| 发送方式 | 是否支持 | 说明 |
| --- | --- | --- |
| 手机浏览器摄像头直播 | 支持 | 需 HTTPS + CA 信任；可带麦克风 |
| 手机相册/文件推送 | 支持 | 单文件 ≤ 2 GB；图片可自动轮播 |
| 桌面浏览器屏幕共享 | 支持 | Chrome/Edge 的 `getDisplayMedia`，需用户手势 |
| DLNA 媒体推送 | 支持 | 第三方 App 发起；受编码与 DLNA 实现限制 |
| 手机整屏镜像 | 不支持 | 浏览器无法捕获系统屏幕 |
| 手机系统声音直播 | 不支持 | 仅麦克风；屏幕共享可带标签页音频 |
| 公网投屏 | 不支持 | 无 STUN/TURN/中继 |

## 5. 功能需求

### FR-01 连接入口

桌面空闲态展示：

- HTTP 与 HTTPS 两种二维码；
- 6 位配对码（5 分钟有效，过期自动轮换）；
- 局域网地址可复制；
- CA 下载入口与信任引导；
- 当前设备名与监听状态。

验收：二维码内容分别指向 `http://<ip>:<port>/#t=<ticket>` 与 `https://...`；配对码为 6 位数字；地址变化（网卡/IP 改变）后 30 秒内刷新展示。

### FR-02 配对

1. 手机打开网页，输入/扫码带入 ticket，填写设备名（默认按 UA 推断）。
2. 服务端生成 60 秒有效的配对请求，桌面弹出审批卡片，展示设备名、平台、IP。
3. 电脑选择"允许并记住"或"拒绝"。
4. 允许后手机获得 30 天会话 Cookie；记住的设备同时获得设备凭据，可在 Cookie 丢失后恢复。

规则：

- 配对码错误返回统一错误文案，不泄露正确码；
- 同一 IP 5 分钟内最多 6 次错误尝试，全局 10 分钟 30 次；
- ticket 120 秒有效，使用一次即轮换；
- 同一 `clientId` 重复配对更新设备记录，不产生重复条目；
- 设备名清除控制字符，最长 40 字符；
- 已被禁用的设备直接拒绝。

验收：`tests/e2e/cast.spec.ts` 的配对与错误码用例；`tests/e2e/security.spec.ts` 的会话、限速用例；`tests/integration/pairing.test.ts`。

### FR-03 会话与设备管理

- 会话令牌格式 `v1.<deviceId>.<exp>.<nonce>.<hmac>`，30 天有效；
- Cookie：`ep_session`、`Path=/`、`HttpOnly`、`SameSite=Strict`、HTTPS 下 `Secure`、`Max-Age=2592000`；
- 桌面可查看设备列表（名称、平台、IP、最后在线、是否记住），可移除设备；
- 手机可主动退出登录；退出后令牌立即失效；
- 设备最多保留 500 台；未记住且 30 天未活跃的设备自动清理。

### FR-04 媒体上传与播放

- 支持图片、音频、视频；MIME 与扩展名双重归一化；
- 单文件上限 2 GB；空文件返回 400；不支持的类型返回 415；
- 单设备 5 分钟最多 30 次上传；
- 上传落盘 `uploads/`，7 天后在应用启动时清理；桌面可"清空上传"；
- 图片默认 8 秒自动轮播（可关，2000–600000 ms 可调）；
- 视频/音频支持播放、暂停、进度、音量、静音、上一项/下一项；
- 上传时若正在直播，进入待播队列，直播结束后可播；
- 服务端支持 `Range`，媒体 URL 只允许回环地址访问。

验收：`tests/e2e/cast.spec.ts`（上传/解码）、`tests/integration/presentation.test.ts`、`tests/unit/media.test.ts`。

### FR-05 摄像头直播（手机）

流程：选择"摄像头"→ 开启麦克风（可选）→ 请求直播 → 桌面审批 → WebRTC 建连 → 桌面显示。

- 视频约束：`facingMode` 理想值、1280×720、30fps；失败时降级为仅 `facingMode`；
- 音频：回声消除、降噪、自动增益；
- 可前后摄像头切换（`replaceTrack`，不断流）；
- 编码上限 4 Mbps、30fps，`degradationPreference=balanced`；
- 桌面可静音、调音量、停止；手机可主动结束；
- 审批 60 秒未处理自动取消；批准后 25 秒内未收到 offer 自动结束；
- 断线有 8 秒宽限，可恢复；
- 同一时刻只允许一个直播；新请求可选择"结束原投屏并接管"；
- 自动批准开启时跳过直播审批（安全权衡见 ADR-014）。

验收：`tests/e2e/cast.spec.ts`（Chromium 假摄像头、真实 WebRTC）、`tests/unit/protocol.test.ts`、`tests/integration/pairing.test.ts`。

### FR-06 桌面浏览器屏幕共享

- 仅在桌面平台且 `navigator.mediaDevices.getDisplayMedia` 可用时展示入口；
- 首选 1920×1080/30fps + 音频；不支持音频或约束失败时降级为纯视频；
- 编码上限 8 Mbps，优先保持分辨率；
- 用户停止共享（浏览器原生"停止共享"）时自动结束会话；
- 仍需桌面审批（与摄像头一致）。

验收：`tests/e2e/cast.spec.ts` 使用真实 `getDisplayMedia` + Chromium 自动选源，验证桌面 `<video>` 解码、快照状态为 `screen`。

### FR-07 DLNA 渲染器

- SSDP 发现：响应 `M-SEARCH`，通告 `MediaRenderer:1`、设备 UUID、三个服务；
- 设备描述、SCPD、SOAP 控制、GENA 事件；
- 支持 AVTransport：`SetAVTransportURI`、`Play`、`Pause`、`Stop`、`Seek`、`Next/Previous`、查询类动作；
- RenderingControl：音量、静音、预设；ConnectionManager：协议信息、连接信息；
- 与直播互斥：直播中收到 DLNA 推送返回忙碌错误；
- 控制端点只接受私网/回环来源；回调地址必须与订阅者 IP 一致；
- 事件订阅 120–3600 秒，初始事件立即发送，变化 ≤1 秒内推送。

验收：`tests/e2e/dlna.spec.ts` 的 5 个用例（发现/描述、GENA、真实图片推送与状态、错误码、退订）。

### FR-08 接收界面

- 空闲：品牌、连接卡片（二维码/配对码/地址/CA）、最近历史；
- 直播：全屏视频、设备名、分辨率/码率/延迟、静音/音量/停止；
- 媒体：图片/视频/音频、队列、进度、轮播开关、音量；
- 审批覆盖层：设备信息、媒体类型、允许/拒绝/接管，键盘可达；
- 提示：Toast 状态播报，错误可关闭。

### FR-09 设置

| 设置 | 默认 | 范围/说明 |
| --- | --- | --- |
| 设备名称 | 主机名 | ≤40 字符 |
| HTTP / HTTPS 端口 | 7333 / 7443 | 1024–65535；冲突时向后顺延最多 9 个端口 |
| 自动批准 | 关 | 跳过配对与直播审批，需明确警告 |
| 启用 DLNA | 开 | 与直播互斥 |
| 启用直播 | 开 | 关闭后手机端隐藏摄像头/屏幕入口 |
| 关闭到托盘 | 开 | 关闭窗口不退出 |
| 开机启动 | 关 | Windows 登录项 |
| 音量 | 85% | 0–100% |
| 图片轮播间隔 | 8000 ms | 2000–600000 ms |
| 日志级别 | info | debug/info/warn/error |

另提供：安装防火墙规则（TCP 双端口 + UDP 1900）、打开数据/日志目录、清空上传、复制诊断信息。

### FR-10 历史与日志

- 历史最多 200 条，记录类型、协议、标题、设备、起止时间、时长、分辨率、编码、平均码率、结束原因；
- 日志按天写 JSONL，保留 14 天，内存保留最近 500 条，界面显示最近 400 条；
- 日志字段按键名脱敏：`token/secret/cookie/authorization/ticket/credential/password`；
- 无任何遥测或外发请求。

## 6. 关键交互流程

### 6.1 首次连接

```
手机扫码/输入 URL
  → 网页加载（HTTP 或 HTTPS）
  → 输入配对码 + 设备名
  → POST /api/pair/code
  → 桌面审批覆盖层
  → 允许并记住
  → 手机收到 ep_session Cookie
  → 进入投送页
```

### 6.2 摄像头直播

```
手机点击摄像头 → getUserMedia → 建立 WS
  → intent(camera, audio)
  → 桌面审批（或自动批准）
  → ready → 手机 createOffer → WS offer
  → 桌面 setRemoteDescription/createAnswer
  → ICE 双向交换（host candidate）
  → 桌面 ontrack 播放
  → 统计上报（分辨率/码率/RTT/丢包）
  → 任一方停止 → ended
```

### 6.3 DLNA 推送

```
控制器 SSDP M-SEARCH → EasyPush 200 OK + LOCATION
  → GET description.xml / SCPD
  → SUBSCRIBE event/AVTransport → 初始 NOTIFY
  → SetAVTransportURI(CurrentURI, DIDL)
  → Play
  → 桌面加载并播放
  → GetTransportInfo = PLAYING
  → GENA LastChange 推送
  → Stop → NO_MEDIA_PRESENT
```
